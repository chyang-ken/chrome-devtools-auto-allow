auto-allow 基建 · 怎么结合进你的 Agent 环境

解决的问题：新版 Chromium 浏览器在外部程序连接「已运行的浏览器」做远程调试时，可能弹出「允许远程调试 / An external app wants full control」框。这个 macOS 工具覆盖 Chrome（Stable / Beta / Dev / Canary）、Chromium 与 Edge 家族，在该弹框时自动点掉「允许」，让 agent 浏览器任务不卡，又不永久拆掉确认防线。

① 它怎么「接」进 agent 环境 —— 挂在「每次跑 bash 命令之前」的钩子上

Claude Code

~/.claude/settings.json
→ hooks.PreToolUse → matcher "Bash"
→ command: …/agent-hook.sh

Codex

~/.codex/hooks.json
→ PreToolUse → matcher "Bash|exec_command|functions\.exec_command"
→ command: …/agent-hook.sh
关键概念：它不绑任何「浏览器工具」，而是绑「agent 要跑一条 bash 命令」这个通用动作。Claude Code / Codex 在真正执行你的命令之前，会先把命令喂给 agent-hook.sh 过一眼。这一层叫 PreToolUse hook——你当初就是在这两个配置文件里各加了一行，把这个基建「焊」进了两个 agent。

② 四个零件，各管一段

agent-hook.sh
触发层。连接特征是快路径；未知工具进入真实连接探测；纯查看命令（ls/git/echo）秒放过。
browser-targets + conn-arm
只从运行中的受支持浏览器发现真实调试端口；多浏览器各留基线，盯「新冒出来的外部连接」，不扫全机端口。
on-demand.sh
看守开关。watch N = 开 N 秒看守（到点自杀）；stop = 立即关；status = 查状态。是「按需、非常驻」的闸。
cdp-auto-allow.scpt
执行层（AppleScript）。每 0.4 秒扫一次 Chromium 家族及其 PWA，只对「远程调试授权框」（三重校验）点「允许」。

③ 一条龙：从你跑命令，到框被自动点掉

1
你让 agent 跑一条要连浏览器的命令Claude Code/Codex

脚本名字和调用方式都不重要；它可以连接任一受支持浏览器或自定义数据目录。

2
执行前，命令先被 hook 拦一眼agent-hook.sh

PreToolUse 钩子触发。明确连接特征会抢先点火；其他未知工具先建立端口基线再放行。（纯 ls/git/echo 直接放过。）

3
命令开始跑、脚本连上目标浏览器Chromium 家族

这一刻，对应浏览器自己的调试端口上多出一条新的 TCP 连接。

4
探测器看到「新连接」→ 叫开看守conn-arm.shon-demand.sh

它对比基线、发现端口上冒出这条新连接（=这条命令发起的），就调 on-demand.sh watch 把看守打开。

5
看守每 0.4 秒扫一次，逮到那个框 → 自动点「允许」cdp-auto-allow.scpt

先三重校验确认是「远程调试框」（有 Allow 按钮 + 有 Cancel + 文字含 debug/remote），才点。你别的弹框永远不碰。

6
连接结束 / 没框了 → 看守到点自杀，防线恢复on-demand.sh

窗口只贴合「这条命令真连浏览器的那几秒」，不长开。下次再有连接，重走一遍。

④ 三条安全闸（为什么它不算「拆防线」）

① 按需启动、到点自杀 —— 非 7×24 常驻 ② 只点「远程调试框」三重校验 —— 别的敏感框不碰 ③ 窗口贴合实际连接 —— 不敞开整个活跃期

设计状态：不安装 launchd 常驻进程；空闲时看守应为 stopped。只用 watch 的短窗口，连接结束后自动收口；start 仅供人工调试。

⑤ 你手动能用的命令

on-demand.sh status查看此刻看守开没开、还剩几秒
on-demand.sh stop立即关掉看守（防线立刻恢复）
doctor.sh体检：检查 hook 注册、依赖、权限是否就位
install.sh / uninstall.sh装 / 卸（就是往那两个 agent 配置里加 / 删那行 hook）

诊断日志：/tmp/cdp-auto-allow.hook.log（哪些命令触发了）、/tmp/cdp-auto-allow.debug.log（scpt 扫到/点了哪些框）。排查时主要看这几个。
